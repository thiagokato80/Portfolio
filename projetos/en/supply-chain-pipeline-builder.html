Supply Chain Pipeline Builder

Visual builder for analysis and demand forecasting pipelines

A no-code tool where the analyst builds data flows by connecting cards on a canvas — ETL, inventory classification, Monte Carlo simulation and time-series forecasting — and exports the finished pipeline as a Python script.

The problem

Supply chain analysis lives in a no-man's-land: too complex for a spreadsheet, too specific for a BI tool, and too frequent to become a data engineering project every time.

The analyst who knows the business rule — how to classify inventory, what service level to use, what is seasonality and what is noise — usually does not write the Python that does the maths. And whoever writes the Python does not know the rule.

The solution

A canvas where each card is an operation and the connections are the data flow. Available columns are detected automatically from the previous card, and each step previews its result — the analyst watches the transformation happen instead of discovering the error at the end.

  • 15 ETL operations — filter, conditional calculation, join, aggregation, pivot, dates, text, deduplication, union, type casting, null handling.
  • Inventory analysis — ABC/XYZ classification, safety stock, reorder point and economic order quantity, with automatic period conversion.
  • Monte Carlo for cost-optimised safety stock, over more than 10,000 simulations.
  • Forecasting — simple, weighted and exponential moving averages, plus ARIMA/SARIMA with confidence bands and per-group support, with MAE, RMSE and MAPE accuracy metrics.
  • Validation before execution, with an instant local check and deep backend analysis, pointing to the exact card behind each problem.
  • Export as code — any pipeline becomes an executable Python script or Jupyter notebook, generated entirely in the browser.

Export as code is the most important product decision: the tool does not hold the work hostage. What was built on the canvas comes out as readable Python that runs without it.

Current chapter: planned demand integration

The work in progress connects the Pipeline Builder to a corporate planning system, so that forecasting stops being an isolated exercise and starts feeding the operation's planned demand.

It is the most interesting transition in the project: moving from an analysis tool, where the result is a chart someone interprets, to a system component, where the result is a number another process consumes — with the data-contract rigour and reproducibility that this demands.

Outcome

Analyses that depended on an available developer are now built by the people who know the business rule. And the pipeline built on the canvas is not trapped in the tool: it comes out as code.
