Match Hub

AI-driven standardisation and matching of hospital supplies

A multi-tenant SaaS platform that normalises hospital supply descriptions with an LLM, generates semantic embeddings, and finds equivalent items across catalogues that never spoke the same language.

Multi-tenant Vertex AI GCP
193 automated tests
768 dimensions per embedding
2 Cloud Run services, one image

The problem

Every hospital, distributor and manufacturer describes the same item differently. "10ml BD syringe", "SYR DISP 10 ML" and "disposable syringe 10 mL w/ needle" are one product to a buyer and three different products to an ERP.

Without a common catalogue there is no reliable price comparison, no purchase consolidation and no consumption analysis. Manual standardisation does not scale: a catalogue of tens of thousands of items consumes months of specialist work and goes stale while it is being built.

The solution

Match Hub normalises the description with Gemini Flash, generates a 768-dimension embedding using text-multilingual-embedding-002, and searches for similar items in Vertex AI Vector Search. A second LLM pass re-ranks the candidates, and anything that stays ambiguous goes to a human curation queue instead of silently becoming a wrong match.

  • Multi-tenant with API-key isolation — each client sees only its own data.
  • Central canonical catalogue, with a proposal and approval flow.
  • Asynchronous import via Cloud Tasks, in batches of 5,000 items, without blocking the API.
  • Pull connector for ERPs — the Hub pulls the catalogue and stops for review, rather than processing everything automatically.
  • Promotion of items between bases reuses the description, embedding and category already processed, without reprocessing through the LLM and without charging twice.

In production it runs as two Cloud Run services from the same image, separated by the SERVICE_ROLE variable: one serves requests, the other consumes the queue.

Outcome

Standardising an entire catalogue went from a months-long project to an asynchronous run tracked on screen. Human work stopped being data entry and became deciding the cases the AI flagged as uncertain.

The caching and promotion architecture was designed around one cost detail: processing the same item twice is money thrown away when processing is an LLM call.
