CyberSec Cockpit

Security testing orchestration with AI-audited authorisation

An internal agentic pentest framework: agents plan the test dynamically, chain SAST, SCA, DAST and network tools, and no scan begins until the authorised scope has been verified.

Security Agents Pipelines
4 layers: SAST, SCA, DAST and network
3 LLM providers routed by cost

The problem

Security testing has two difficulties that are not technical. The first is chaining: every tool speaks its own language, and correlating a static-analysis finding with a dynamic-scan finding is manual work that gets lost between reports.

The second is more serious — scope. Scanning something that was not authorised is not a configuration error, it is a legal problem. And the authorisation document is usually a PDF someone read once.

The solution

The rule that organises the whole system is authorisation-first: the authorisation document is audited by AI and the scope extracted from it governs what may be executed. Non-intrusive discovery feeds the agents, and only after scope validation can an intrusive lab be triggered.

  • Dynamic planning by agents, routing between LLM providers by cost and task fit.
  • Human review mid-flow — triage and validation before the report is generated. The AI accelerates; the specialist decides.
  • Chained integration of static, dependency, dynamic and network analysis in a single chain.
  • Asynchronous pipelines on Celery and Redis, with real-time status over WebSockets.

Outcome

Traceability stopped depending on operator discipline and became a property of the system: every run ties back to a verified authorisation. And chaining between tools became a pipeline rather than the work of correlating reports by hand.
